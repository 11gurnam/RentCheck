# Phase7 — What to check

Open http://127.0.0.1:3000 with Docker running. Use fictional renter/admin accounts from local-demo-accounts.md; keep admin in a separate browser/incognito window. Your Google account remains ordinary.

1. As renter, open a property with a fictional tenant review. Expand “Report this review”, enter “Fictional concern for investigation” and submit. Expect confirmation that the review remains visible; refresh and confirm its text/rating still appears.
2. As demo admin, open /admin/reports. Read the reported text/reason, choose Keep review, enter “Reviewed the fictional concern; keep this account” and save. Expect kept and unchanged public text. An ordinary account must see Access restricted.
3. To test removal, use a different fictional account to report the same review (each reporter submits once). Admin chooses Remove review with a reason. Refresh public profile: expect that review, its photos/replies and rating contribution gone. /admin/audit retains report_decision and reason.
4. On /admin/associations choose a property and Inspect management history. Add a manager period after its existing period ends; end dates are exclusive. An overlapping period must be refused. To correct a period, choose it under Association to replace. Old tenant reviews must keep their original manager links/ratings. Add only fictional manager names under “Add a fictional manager”; an exact duplicate is refused.
5. For the merge check, create TWO fictional properties with different addresses in the SAME state/city (example names “Demo Merge Source 07” and “Demo Merge Target 07”). Do not mark either as your own. Write one review on each from the SAME renter account with the SAME start date; save both to shortlist.
6. Admin opens /admin/merge, selects source to archive and target to keep, then Inspect both profiles. Read both profiles/tenancies/claims/history. Select which profile details and management history to retain, enter a reason and confirm reviewed resolutions. Submit without selecting a losing review: expect refusal about repeated/overlapping tenancies; both profiles/saves remain.
7. Deliberately select ONE losing review under “Reviews to archive as conflict losers”. If competing active claims exist, explicitly select claims to revoke; unresolved conflicts refuse the whole merge. Save: expect successful transaction, target visible with the kept review, source404, one shortlist target and immutable property_merge audit. The losing author’s dashboard says archived; records were retained, not overwritten.
8. /admin/duplicates lets you inspect automatically flagged similar profiles or keep them distinct with a reason. Similarity alone never merges them.

Use unique fictional names/addresses so your examples are easy to find. Merge only the two walkthrough examples; it changes their local records. Report step/page/expected/actual without passwords. Automated cases use isolated disposable fixtures; your manual examples persist. User manual status: NOT RUN.
